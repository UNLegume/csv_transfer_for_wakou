# 注文・CSV出力の状態モデル

## 基本方針

Shopifyは注文データの正本です。このアプリはShopifyへ注文・商品・発送状態を書き込みません。
アプリ内で永続化するのは、個人情報を含まないCSV出力履歴だけです。

## CRUDの責務

| 対象 | Create | Read | Update | Delete |
|---|---|---|---|---|
| Shopify注文 | 対象外 | 注文取得時に読取り | 対象外 | 対象外 |
| 注文プレビュー | 注文取得時に15分間だけ作成 | 「未出力の注文」タブ | 配送会社の一時変更と選択状態 | CSV出力成功後に対象注文だけ削除 |
| CSV出力履歴 | CSV生成後、レスポンス返却前に追記 | 「出力済み一覧」タブ | 更新しない。再出力は新しい履歴として追記 | 削除しない |

プレビューは単一プロセスのメモリ内状態です。プロセス間では共有されないため、アプリは
必ず単一worker（`--workers 1`）で運用します。

## 画面の状態遷移

1. 「Shopifyから注文取得」で一時プレビューを作成する。
2. 過去に出力していない注文だけを「未出力の注文」に表示する。
3. チェック状態とヤマト／佐川の変更はブラウザ内の一時状態として保持する。
4. 複数注文を選択した場合、ヤマトボタンはヤマトに設定された注文だけ、佐川ボタンは佐川に設定された注文だけを出力する。
5. 一方のCSVを出力しても、もう一方の配送会社に属する選択状態は維持する。
6. CSV生成と履歴保存が成功した注文だけを未出力一覧から除外する。
7. 出力記録は「出力済み一覧」へ即時反映する。
8. 注文を再取得しても、出力済み注文は未出力一覧へ戻さない。

状態境界はCSV生成後の履歴追記です。履歴追記が成功した時点で注文を「出力済み」とし、
その後のブラウザ側でのファイル保存や印刷の成否は状態境界に含めません。履歴追記に失敗した
場合は注文をプレビューから除外せず、出力済み記録も残しません。

再出力時は、履歴の注文IDを最新プレビュー内の注文IDと対応付けます。プレビューはCSV出力後に
対象注文を削除するため、対象注文を含む注文期間をShopifyから再取得して新しいプレビューを
作成し、再出力理由を入力して出力します。理由なしの再出力は拒否し、履歴を追記しません。

## 配送会社変更

- 自動判定結果は参照値として保持する。
- 出力先を変更するときだけ変更理由を必須にする。
- 「要確認」の注文には初期の出力先を設定しない。
- 「要確認」で出力先が未選択の注文へ初めてヤマトまたは佐川を指定する場合、変更理由は要求しない。
- 配送会社の変更はShopify商品や注文へ書き戻さない。

## 出力履歴

保存する項目：

- バッチID
- Shopify注文ID
- 注文番号
- 配送会社
- 出力日時
- 再出力理由

保存しない項目：

- 氏名
- 住所
- 郵便番号
- 電話番号
- 商品明細

履歴は監査記録として追記専用にし、画面から削除・編集しません。
履歴APIが返す注文IDはプレビューとの対応付けに使う非PIIの識別子です。履歴APIも、保存しない
項目として挙げた個人情報や商品明細を返しません。
履歴は100件単位でページングし、注文番号検索も提供します。最新100件より古い注文も検索または
「さらに表示」で到達でき、対象期間の注文を再取得した後に再出力できます。
